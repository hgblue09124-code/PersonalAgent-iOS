# M3 — Module / Skill / Tool Runtime

Status: module contract and runtime implemented. Privileged device tools are not shipped. Memory engine is not M3.

## Semantics

- A **Tool** is an executable capability with typed input/output (`PATools`).
- A **Module** is an explicit capability boundary with identity, version, schemas, capabilities, and lifecycle (`PAModules`).
- A **Skill** is a higher-level compositional capability. It may invoke modules/tools through their contracts. It must not bypass them.

These are not collapsed into one type.

## Timeout and cancellation

Timeout and cancellation are cooperative. Modules must honor `Task.checkCancellation` at await points. Swift cannot hard-preempt a body that ignores cancellation. The runtime still returns `.timeout` / `.cancelled` and never emits `.moduleCompleted` for that invocation.

## Payload contract

`ModulePayload` is a schema-tagged `[String: String]`, not a Swift generic and not a JSON Schema engine. Runtime enforces schema identifier match on input and output, plus non-blank `requiredFields` on input.

## Dependencies

`ModuleContract.dependencies` are catalog edges. Registration rejects missing dependencies and cycles. The catalog does not execute the graph.

## Skill and Tool execution paths

```
Skill-as-Module (EchoSkillModule) → ModuleRuntime → child Module
Tool → ToolModule → ModuleRuntime
```

`SkillExecuting` and `ToolExecuting` are future seams, not a second engine.

## Implemented

- Schema-tagged `ModulePayload`. No `[String: Any]`.
- `ModuleCatalog` actor: explicit register/resolve, duplicate / missing / cycle rejection.
- `ModuleRuntime` actor: validate, capability grant, cooperative timeout/cancel, output schema check.
- Deterministic modules including hang, uncooperative resistant (no await), wrong-output, cycle fixtures, echo skill, failing-echo child, echo/hang/privileged tools.
- Kernel holds `any ModuleExecuting` and requests execution via `AgentRuntime.invokeModule`.
- Default composition grant is `.read/.write/.execute`. Destructive modules are registered but denied.

## Out of scope

- Memory engine (M4)
- Full skill store / discovery
- Privileged filesystem, network, or device tools
- Cognition loop calling modules autonomously
- Hard preemption of uncooperative module bodies
