# M4 Memory OS Specification & Architecture

Status: IMPLEMENTED — AWAITING INDEPENDENT DEEP AUDIT

M4 implements a contract-driven, local-first, deterministic, concurrency-safe, and queryable Memory OS subsystem for Personal Agent.

---

## 1. M4 Responsibility
- Manage agent memory state as a first-class subsystem outside LLM reasoning and UI layers.
- Provide durable local-first persistence with atomic disk writes and schema versioning boundaries.
- Provide indexed search and multi-field filtering over memory records.
- Enforce strict dependency direction: Kernel interacts only with the `MemoryExecuting` protocol port.

---

## 2. Memory Model & Lifecycle
- **Memory Kinds**: `working`, `episodic`, `semantic`, `preference`, `procedural`, `fact`, `event`, `context`, `instruction`, `observation`.
- **Lifecycle Concept**: `capture` → `validate` → `store` → `retrieve` → `consolidate` → `update` → `forget`.
- **Memory Record Attributes**:
  - `id: MemoryRecordID` (stable identity)
  - `kind: MemoryKind`
  - `content: String`
  - `provenance: Provenance`
  - `scope: MemoryScope` (`agent`, `session`, `conversation`, `global`)
  - `lifecycle: MemoryLifecycle` (`created`, `active`, `updated`, `archived`, `deleted`)
  - `importance: Double` (0.0 to 1.0 score; non-finite or out-of-range values fail closed)
  - `metadata: MemoryMetadata` (`[String: String]` key-value map)
  - `version: Int` (incremented on update; update checks optimistic concurrency)

---

## 3. Runtime & Storage Boundaries
```
AgentRuntime (Kernel)
      ↓ (MemoryExecuting port)
MemoryRuntime (Actor)
      ↓ (MemoryStore protocol)
FileBackedMemoryStore / InMemoryMemoryStore (Actor)
      ↓ (MemoryIndex)
Local Storage (Atomic JSON Snapshot store.json)
```

- **Kernel Seam**: `KernelCoordinationBoundary` exposes `public var memory: (any MemoryExecuting)?`. Kernel code never references `FileBackedMemoryStore` or concrete file APIs.
- **UI Seam**: App/UI code does not import `PAMemory` or own `MemoryStore`.
- **Modules / Providers / Skills / Tools Seams**: `PAModules`, `PASkills`, `PATools`, and `PAProviders` do not import `PAMemory`.
- **Composition Wiring**: `M4CompositionRoot` in `PAComposition` owns concrete initialization and wires `MemoryRuntime` and `FileBackedMemoryStore`.

---

## 4. Query & Retrieval Complexity
- **`retrieve(id)`**: $O(1)$ direct hash map lookup.
- **`retrieve(kind, limit)`**: $O(1)$ index lookup + candidate slice. Rejects `limit <= 0` with `MemoryError.invalidQuery`.
- **Filtered Query**: Candidate Set intersection over indexed fields (`scope`, `kind`, `lifecycle`, `metadata`).
- **Lexical Text Search**: Tokenized inverted word index candidate Union.
- **Relevance Sorting**: $O(M \log M)$ over $M$ candidate records ($M \le N$).
- **Reload from Disk**: $O(N)$ JSON decode and index reconstruction.

---

## 5. Persistence Boundary & Transactional Integrity
- **`FileBackedMemoryStore`**:
  - Uses a single unified snapshot (`store.json`) containing metadata and records.
  - Uses `Data.write(to:options: .atomic)` for single-file atomic snapshot replacement. On write failure, in-memory state rolls back to the previous committed state.
  - Version metadata: Schema version set strictly to `1`. Non-matching schema versions (`!= 1`) throw `MemoryError.unsupportedVersion`. Corrupt disk data throws `MemoryError.corruptRecord` and fails closed.
  - `reload()`: Disposes in-memory indexes, re-reads `store.json` from disk, rebuilds index.
  - **Durability & Platform Limitations**: Atomic file replacement depends on underlying platform filesystem semantics (`Data.write(..., .atomic)` uses a temporary auxiliary file and rename). It does not guarantee absolute hardware-level power-loss or OS crash durability if the underlying OS storage driver delays syncing dirty file pages (`fsync`) to non-volatile physical storage media.
