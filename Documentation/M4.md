# M4 Memory OS — Architecture & Runtime Specification

Status: IMPLEMENTED & VERIFIED

M4 implements a contract-driven, local-first, deterministic, concurrency-safe, and queryable Memory OS subsystem for Personal Agent.

---

## 1. Architectural Baseline & Rules

The Memory subsystem is built as a first-class subsystem following strict dependency direction rules:

```
AgentRuntime (Kernel)
      ↓ (MemoryExecuting coordination port)
MemoryRuntime (Actor)
      ↓ (MemoryStore protocol)
FileBackedMemoryStore / InMemoryMemoryStore (Actor)
      ↓
Disk Persistence (Atomic JSON + Schema Versioning)
```

### Boundary Constraints
- **Kernel Isolation**: `PAKernel` imports only the `MemoryExecuting` protocol seam. It has zero dependencies on `FileBackedMemoryStore` or `InMemoryMemoryStore`.
- **UI Isolation**: App screens and UI components do NOT import `PAMemory` or access `MemoryStore` directly.
- **Provider & Skill Boundary**: `PAProviders`, `PASkills`, `PATools`, and `PAModules` do NOT import `PAMemory`.
- **No Global State**: Zero singletons, zero service locators, zero global mutable dictionaries.

---

## 2. Strong Typed Memory Contracts

Defined in `PAMemory` (`Sources/Memory/MemoryContracts.swift`):

- **Identity**: `MemoryRecordID` (UUID-backed stable raw representable value).
- **Provenance**: `Provenance` (expressing source e.g. `user`, `agent`, `conversation`, `tool`, `module`, `system`, `importSource`).
- **Scope**: `MemoryScope` (`agent`, `session`, `conversation`, `global`).
- **Lifecycle**: `MemoryLifecycle` (`created`, `active`, `updated`, `archived`, `deleted`).
- **Taxonomy / Kinds**: Extensible `MemoryKind` taxonomy (`working`, `episodic`, `semantic`, `preference`, `procedural`, `fact`, `event`, `context`, `instruction`, `observation`).
- **Metadata**: `MemoryMetadata` (strongly-typed key-value dictionary wrapper).
- **Importance**: Bounded score (0.0 ... 1.0) with relevance scoring helpers.
- **Query & Result**:
  - `MemoryQuery`: Composable multi-field search filter (ID, Scopes, Kinds, Lifecycles, Time range, Metadata filters, Full-text search, Min importance, Limit, Sort order).
  - `MemoryQueryResult`: Contains matched records, total match count, and execution duration nanoseconds.
- **Error Semantics**: Fail closed with typed `MemoryError` (`notFound`, `duplicateID`, `persistenceFailed`, `corruptRecord`, `schemaMismatch`, `invalidQuery`, `concurrentConflict`, `unsupportedVersion`). Never uses `try?` on critical storage paths.

---

## 3. Storage Engine & Local-First Persistence

Implemented in `FileBackedMemoryStore` (`Sources/Memory/FileBackedMemoryStore.swift`):

- **Pure Swift Implementation**: Self-contained using `FileManager`, `Data`, `JSONEncoder`, and `JSONDecoder`. Zero external third-party dependencies.
- **Atomic Writes**: Uses `Data.write(to:options: .atomic)` to guarantee crash and power-loss safety without corrupt or partial writes.
- **Schema Versioning Boundary**: Store metadata records `version = 1`. Incompatible schema versions throw `MemoryError.unsupportedVersion(version)` and fail closed.
- **Process Restart & Reload**: Store supports `reload()`, clearing in-memory index structures and re-reading disk records to rebuild indexes on startup or process recreation.

---

## 4. Query & Indexing Engine

Implemented in `MemoryIndex` (`Sources/Memory/MemoryIndex.swift`):

- **In-Memory Multi-Field Indexes**:
  - `idMap: [MemoryRecordID: MemoryRecord]` — $O(1)$ ID lookup latency.
  - `scopeIndex: [MemoryScope: Set<MemoryRecordID>]` — $O(1)$ Scope filter.
  - `kindIndex: [MemoryKind: Set<MemoryRecordID>]` — $O(1)$ Kind filter.
  - `lifecycleIndex: [MemoryLifecycle: Set<MemoryRecordID>]` — $O(1)$ Lifecycle filter.
  - `metadataIndex: [String: [String: Set<MemoryRecordID>]]` — Metadata key/value candidate set intersection.
  - `invertedWordIndex: [String: Set<MemoryRecordID>]` — Tokenized lowercased inverted word index for keyword and full-text search.
- **Composable Filtering & Relevance Ranking**:
  - Intersects index candidate sets for combined queries.
  - Supports sorting by `createdAtDescending`, `createdAtAscending`, `importanceDescending`, or `relevance`.

---

## 5. Concurrency Model

- `MemoryRuntime`, `FileBackedMemoryStore`, and `InMemoryMemoryStore` are implemented as Swift `actor`s.
- Guaranteed thread safety under concurrent writes, reads, and queries across parallel `Task`s with zero data races.
- All query parameters (`MemoryQuery`) and query results (`MemoryQueryResult`) conform to `Sendable`.

---

## 6. Forget / Eviction Policy Scope in M4

- **M4 Scope**: Explicit lifecycle management (`active`, `archived`, `deleted`) and explicit `forget(id:reason:)` operations for soft deletion and logical memory removal.
- **Future Scope Boundary**: Automatic background eviction policies (e.g. LRU or memory pressure consolidation) are intentionally reserved for future Cognition/Memory consolidation milestones (M8+), preserving M4 as pure deterministic storage & query OS infrastructure.
