# M2 — Provider Runtime

Status: provider contract and runtime implemented. Live network verification pending. Device sign-off pending.

## Implemented

- Semantic provider contract: identity, configuration, capabilities, request/response, stream events, typed errors.
- `ProviderRuntime` actor owns provider lifecycle (`unconfigured → configured → ready → executing → completed|failed|cancelled`).
- Transport is a separate port (`ProviderTransport`). Tests use `ScriptedTransport`. No `URLSession` in Kernel or Composition.
- Shared OpenAI-compatible codec maps semantic requests to chat.completions JSON.
- Concrete adapters exist for Grok, OpenAI, OpenAI-compatible, and Local. They are translation layers over injected transport + credential refs.
- `DeterministicFakeProvider` is the default composition provider. App launch does not open a network session and does not load production credentials.
- Credentials stay in `PASecurity` / `CredentialResolving`. Event payloads store `hasCredentialRef`, never secret material.
- Kernel may hold `any LLMProvider` on `KernelCoordinationBoundary`. Kernel does not import concrete provider modules and does not invoke the provider in M2.
- Automatic retries are classified (`RetryClassification`) and not executed.

## Lifecycle

```
unconfigured --configure--> configured --ready--> ready
ready --complete/stream--> executing
executing --> completed | failed | cancelled
completed | failed | cancelled may return to ready on the next execute
```

This graph is not `AgentLifecycle`. Stop/pause on the kernel does not change provider lifecycle.

## Security

- No API keys in source control.
- `ProviderCredentialRef` is an account handle.
- Transport may attach `Authorization` for the duration of a request.
- Logs, events, error `description`, and redacted headers must not contain the secret.
