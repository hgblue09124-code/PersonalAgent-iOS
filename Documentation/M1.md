# M1 — Kernel Runtime

Status: implemented kernel runtime. Not a cognition loop. Not a provider.

## Implemented

- `AgentRuntime` actor owns identity, lifecycle, goals, and event emission.
- Lifecycle graph derived from M0 `AgentLifecycle` stable states.
- Goal graph mapped onto M0 `GoalStatus` (`blocked` is goal-suspend).
- Typed `KernelError` for invalid commands. Failed commands do not mutate authoritative state.
- Process-local `InMemoryEventLog` as an observability sink, not storage.
- `KernelCoordinationBoundary` ports exist and are unwired.
- Terminal stop parks an active goal (`active → blocked`) and clears `activeGoalID`.
- Every rejected command emits `commandRejected` with a structured error payload.

## Contract-only / reserved

- Cognition pipeline, agency loop, policy evaluation during execution.
- Provider, skill, tool, memory, sync engines.
- Event replay persistence (M8).
- `AgentLifecycle.failed` is terminal in the graph but M1 has no internal failure injector.
- There is no parked `ready` state. M0 `AgentLifecycle` has no `ready` case. `start` makes the runtime executable.

## Lifecycle

```
created --start--> running
created --stop---> stopped
running --pause--> paused
running --stop---> stopped
paused  --resume-> running
paused  --stop---> stopped
stopped / failed : terminal
```

Repeated start/pause/resume/stop against the same stable state is rejected.

Transient enum cases `starting`, `pausing`, `stopping` are not parked states. Commands are atomic.

## Goal lifecycle

```
(submit) proposed --activate--> active --complete--> completed
                 \--abort--> aborted
active --suspend--> blocked --resume--> active
blocked --abort--> aborted
blocked --complete--> completed
```

Activate/resume-goal require `lifecycle == running`.
At most one active goal.
Submit is allowed in `created` / `running` / `paused` and rejected after a terminal lifecycle.

## Invariants

- Identity is immutable for the lifetime of the runtime.
- Parked lifecycle is always a stable state (`created`, `running`, `paused`, `stopped`, `failed`).
- `lifecycle == running` ⇔ runtime is executable.
- `activeGoalID != nil` ⇒ referenced goal exists, `status == active`, and lifecycle is not terminal.
- `lifecycle == stopped` ⇒ `phase == completed` and `activeGoalID == nil`.
- Pause keeps the active-goal pointer; stop parks it.

## Events

Command success emits one typed `ExecutionEvent` on the session trace (stop may first emit `goalBlocked` when parking).
Rejected commands emit `commandRejected` and leave state unchanged.
Identical command sequences emit identical kind streams.

## Concurrency

`AgentRuntime` is an actor. It is the only mutable-state owner for a kernel instance.
No `@unchecked Sendable` in the kernel.
Clock and event log are injected; the system clock is not required for kind-stream determinism.

## Composition

`M1CompositionRoot` constructs identity + in-memory log + runtime.
`M0CompositionRoot` remains as the honest skeleton (no runtime).
The SwiftUI shell holds a `KernelSession` that forwards commands. It does not own goals or lifecycle.
The Xcode app target links `PAComposition`, `PAArchitecture`, `PAFoundation`, and `PAKernel`. It does not link `PAMemory`.
CI on `main` runs `swift test` and greps for `KernelSession.swift in Sources`.
