# M6 Architecture Contract — Cognition Pipeline & Agency Execution Loop Gate

Status: M6 Architectural Gate Specification (Normative).
Milestone Baseline: `cf33fb3906621b39e3ef64fa388909432cfadd46` (`origin/main` merged M5 baseline).

This document establishes the normative architectural specification and contract for Milestone 6 (M6). It governs the integration of Cognition (`PACognition`), Agency (`PAAgency`), Policy (`PAPolicy`), Module Execution (`PAModules`), Provider Execution (`PAProviders`), and Memory Operations (`PAMemory`) into a unified, deterministic runtime pipeline.

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in RFC 2119.

---

## 1. Architectural Purpose & Scope

### 1.1 Architectural Purpose
M6 defines the architectural specification and contract surface for orchestrating the Cognition Pipeline and Agency Execution Loop within the Personal Agent OS framework. It establishes strict runtime rules, actor concurrency boundaries, state mutation constraints, failure propagation models, and policy enforcement mechanisms required to transition goals into deterministic, policy-verified actions executed via providers, skills, modules, tools, and memory.

### 1.2 Non-Goals
M6 contracts MUST NOT dictate:
* Concrete UI presentation frameworks, SwiftUI views, or view-model bindings.
* Live cloud network infrastructure, live cloud endpoint addresses, or vendor-specific API keys.
* Third-party agent framework adapters (e.g. LangChain, AutoGen, CrewAI).
* Autonomous background daemon execution outside of explicit agent runtime lifecycle control.
* Bypassing user approval for high-capability or privileged action execution.

## 2. Forensic Audit & Architectural Map (M0–M5 Baseline)

Based on forensic analysis of the frozen M0–M5 baseline (`cf33fb3906621b39e3ef64fa388909432cfadd46`):

### 2.1 Current Layers and Components
1. **App / UI Layer (`App/PersonalAgent`)**: SwiftUI interfaces and `KernelSession`. Strictly isolated from business logic, providers, storage, and agency.
2. **Composition Layer (`PAComposition`)**: Composition roots (`M1CompositionRoot` through `M4CompositionRoot`) that assemble runtime actors and inject dependencies explicitly.
3. **Kernel Layer (`PAKernel`)**: `AgentRuntime` actor owning state, goals (`GoalMachine`), lifecycle (`LifecycleMachine`), and coordination boundaries (`KernelCoordinationBoundary`).
4. **Cognition Layer (`PACognition`)**: Defines Cognition pipeline stages (`Perception` → `ContextBundle` → `ReasoningResult` → `Plan` → `ActionProposal` → `VerificationResult` → `Reflection` → `StateUpdate`) and protocols (`Planning`, `Executing`, `CognitionPipelining`).
5. **Agency Layer (`PAAgency`)**: Defines Agency loop stages (`goal` → `plan` → `execute` → `observe` → `evaluate` → `adapt` → `continueOrCompleteOrAbort`), evaluations, observations, and protocols (`AgencyLooping`, `ActionAuthorizing`).
6. **Policy Layer (`PAPolicy`)**: Safety and capability evaluation primitives (`PolicyDecision`, `ActionIntent`, `PolicyEvaluating`, `ApprovalGate`).
7. **Skills / Tools / Modules Layer (`PASkills`, `PATools`, `PAMmodules`)**: Modular execution contracts (`Module`, `ModuleCatalog`, `ModuleRuntime`, `Tool`, `Skill`).
8. **Providers Layer (`PAProviders`, `PAProvidersGrok`, `PAProvidersOpenAI`, etc.)**: LLM interface abstractions (`LLMProvider`, `ProviderRuntime`, `HTTPChatProvider`) and isolated provider implementations.
9. **Memory & Storage Layer (`PAMemory`, `PAStorage`)**: Local-first record store (`FileBackedMemoryStore`, `InMemoryMemoryStore`), indexed search (`MemoryIndex`), and local/cloud synchronization engine (`PASyncEngine`, `PASyncQueue`).
10. **Security Boundary (`PASecurity`)**: Secret management (`SecretStore`) ensuring key isolation.
11. **Events & Observability Layer (`PAEvents`, `PAObservability`)**: Auditable event logs (`ExecutionEvent`, `InMemoryEventLog`) and logging bridges.
12. **Foundation Layer (`PAFoundation`)**: Core identifiers, capability levels (`CapabilityLevel`), provenance, errors, and schema definitions.

### 2.2 Ownership Boundaries
* **AgentState & Goal Authorities**: Owned exclusively by `AgentRuntime` in `PAKernel`.
* **Capability Gate & Approvals**: Owned exclusively by `PAPolicy`.
* **Module Execution Boundary**: Owned exclusively by `ModuleRuntime` in `PAModules`.
* **Memory State & Persistence**: Owned exclusively by `MemoryStore` / `MemoryRuntime` in `PAMemory` and `LocalStore` in `PAStorage`.
* **Sync & Cloud State**: Owned exclusively by `PASyncEngine` in `PAStorage`.
* **Composition Authority**: Owned exclusively by `PAComposition`.

### 2.3 Dependency Graph
The enforced downward dependency hierarchy is:
```
App -> PAComposition -> PAKernel -> PAAgency / PACognition / PAPolicy / PAEvents / PAObservability / PAProviders / PAModules -> PASkills / PATools / PAMemory -> PAStorage / PASecurity -> PAFoundation
```

### 2.4 Data & Control Flow
1. **Control Flow**: User/App → `AgentRuntime` → `KernelCoordinationBoundary` → Agency Loop / Cognition Pipeline → Policy Evaluation → Module / Provider / Memory Execution → Event Logging → `AgentRuntime`.
2. **Data Flow**: `Perception` input → Context assembly from `PAMemory` → LLM Reasoning via `PAProviders` → `Plan` generation → `ActionProposal` → `PolicyEvaluating` authorization → `ActionIntent` execution via `PAModules` / `PATools` → `Observation` capture → `Reflection` generation → `MemoryRecord` update via `PAMemory`.

### 2.5 Existing Extension Points
* `KernelCoordinationBoundary` properties: `policy`, `planner`, `executor`, `agency`, `provider`, `modules`, `memory`.
* `Module` and `Tool` protocol conformance.
* `LLMProvider` protocol conformance.
* `MemoryStore` and `PAStorage.LocalStore` protocol conformance.

### 2.6 Frozen M0–M5 Invariants
1. Kernel MUST NOT import concrete providers (`PAProvidersGrok`, `PAProvidersOpenAI`, `PAProvidersLocal`, etc.), SwiftUI, UIKit, or URLSession.
2. Modules, Skills, Tools, and Providers MUST NOT import `PAMemory`.
3. Storage and Memory MUST NOT import Cloud SDKs or vendor implementations directly.
4. All dependency resolution MUST be explicit via Composition injection; no service locators or global singletons SHALL exist.
5. All operations MUST fail closed: errors MUST NOT be silently swallowed with `try?`.
6. Operations modifying memory or store state MUST maintain explicit revision history and version incrementing.

### 2.7 Identified Architectural Debt
1. **Incomplete Cognition/Agency Implementation**: `PACognition` and `PAAgency` contain contract data structures (`Plan`, `Perception`, `Reflection`, `Observation`, `Evaluation`) and protocol definitions (`Planning`, `Executing`, `AgencyLooping`), but lack concrete runtime pipeline orchestrators.
2. **Disconnected Policy Gate in Module Runtime**: `ModuleRuntime` currently enforces capabilities (`grantedCapabilities`) independently of `PAPolicy`'s `PolicyEvaluating` and `ApprovalGate`.
3. **Static Composition Wiring**: `M4CompositionRoot` initializes `KernelCoordinationBoundary` with provider, modules, and memory, but leaves `policy`, `planner`, `executor`, and `agency` as `nil`.
4. **Unused Provider in Kernel**: `AgentRuntime` receives `coordination.provider` but does not currently invoke LLM reasoning during goal lifecycle transitions.

### 2.8 Missing Primitives Required Before M6 Implementation
Before M6 runtime code can be implemented (in M6.1+), the following primitives MUST be formally designed:
1. `CognitionPipeline`: A concrete orchestrator conforming to `CognitionPipelining` executing the 8 cognitive stages.
2. `AgencyLoop`: A concrete orchestrator conforming to `AgencyLooping` running the 7 agency loop stages.
3. `ActionAuthorizer`: A concrete implementation conforming to `ActionAuthorizing` bridging `ActionProposal` to `PolicyEvaluating` and `ApprovalGate`.
4. `M6CompositionRoot`: An updated composition root wiring `CognitionPipelining`, `AgencyLooping`, `ActionAuthorizing`, `PolicyEvaluating`, `LLMProvider`, `ModuleRuntime`, and `MemoryRuntime` into `KernelCoordinationBoundary`.

### 2.9 Explicit Forbidden Boundaries for M6
1. M6 MUST NOT permit `PACognition` or `PAAgency` to mutate `AgentRuntime` lifecycle (`created`, `running`, `paused`, `stopped`, `failed`) directly.
2. M6 MUST NOT permit tools, skills, or modules to execute without prior Policy authorization when capabilities exceed `.read`.
3. M6 MUST NOT permit Cognition or Agency loops to bypass `PAEvents` audit logging.
4. M6 MUST NOT allow direct imports of `PAMemory` inside `PAModules`, `PASkills`, `PATools`, or `PAProviders`.

## 3. M6 System Architecture & Component Specification

### 3.1 Cognition Pipeline Specification (`PACognition`)

The Cognition Pipeline MUST execute in 8 sequential, deterministic stages:

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│ 1.Perception│ ──> │  2.Context  │ ──> │ 3.Reasoning │ ──> │  4.Planning │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
                                                                   │
┌─────────────┐     ┌─────────────┐     ┌─────────────┐            ▼
│8.StateUpdate│ <── │ 7.Reflection│ <── │6.Verificat'n│ <── ┌─────────────┐
└─────────────┘     └─────────────┘     └─────────────┘     │5.ActionProp.│
                                                            └─────────────┘
```

1. **Perception**: Captures input statement and origin provenance.
2. **Context Assembly**: Queries `PAMemory` using relevance and keyword search to build a context bundle.
3. **Reasoning**: Dispatches context bundle to configured `LLMProvider` via `ProviderRuntime`.
4. **Planning**: Transforms reasoning summary into a structured `Plan` containing ordered `PlanStep` items.
5. **Action Proposal**: Derives specific `ActionProposal` instances with explicit `CapabilityLevel` requirements.
6. **Verification**: Validates action proposals against static schema, constraints, and safety invariants.
7. **Reflection**: Evaluates post-execution observations to determine success, failure, or required plan adaptation.
8. **State Update**: Commits resulting knowledge, observations, and state changes to `PAMemory`.

### 3.2 Agency Execution Loop Specification (`PAAgency`)

The Agency Execution Loop MUST orchestrate goal execution across 7 stages:

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  1.Goal  │ ──> │  2.Plan  │ ──> │ 3.Execute│ ──> │ 4.Observe│
└──────────┘     └──────────┘     └──────────┘     └──────────┘
                                                        │
┌──────────────────────────────┐     ┌──────────┐       ▼
│ 7.Continue / Complete / Abort│ <── │  6.Adapt │ <── ┌──────────┐
└──────────────────────────────┘     └──────────┘     │5.Evaluate│
                                                      └──────────┘
```

1. **Goal**: Fetches active active goal from `AgentRuntime`.
2. **Plan**: Invokes `Planning` component of Cognition Pipeline.
3. **Execute**: Passes proposals to `ActionAuthorizing` gate and dispatches approved intents to `ModuleRuntime` / `PATools`.
4. **Observe**: Captures execution outputs and maps them into an `Observation`.
5. **Evaluate**: Computes `Evaluation` containing disposition (`continue`, `complete`, `abort`).
6. **Adapt**: Re-plans or adjusts execution parameters if evaluation indicates failure or unexpected state.
7. **Continue / Complete / Abort**: Mutates goal state in `AgentRuntime` based on final evaluation.

## 4. Policy Enforcement & Security Boundaries

### 4.1 Capability Enforcement
* Every `ActionProposal` MUST specify required `CapabilityLevel` (`.none`, `.read`, `.write`, `.execute`, `.admin`).
* If required capabilities exceed granted capabilities, `PolicyEvaluating` MUST return `PolicyDecision.deny(...)` and execution MUST immediately halt.

### 4.2 Human-in-the-Loop Approval Gate
* If `PolicyDecision.requiresApproval` is `true`, execution MUST NOT proceed automatically.
* The pipeline MUST suspend action execution and query `ApprovalGate.requestApproval(for: intent)`.
* If approval is denied or times out, the action MUST be marked as rejected and execution MUST fail closed.

### 4.3 Auditability & Secret Safety
* All policy decisions, intent authorizations, and execution attempts MUST emit an `ExecutionEvent` to `PAEvents`.
* Secrets, API tokens, and credentials MUST NOT be logged in `ExecutionEvent` payloads or `AgentLogger` metadata.

---

## 5. Concurrency, State & Failure Semantics

### 5.1 Concurrency & Isolation
* `AgentRuntime`, `ProviderRuntime`, `ModuleRuntime`, `MemoryRuntime`, and `PASyncEngine` MUST remain isolated Swift `actor`s or `@Sendable` value types.
* Concurrent goal activations or pipeline invocations MUST be serialized through `AgentRuntime` actor execution.

### 5.2 Determinism & Traceability
* Given identical initial state, seeds, context bundle, and deterministic fake provider/module responses, the Cognition Pipeline and Agency Loop MUST produce identical event sequences.
* Every stage of pipeline execution MUST carry the session `traceID`.

### 5.3 Fail-Closed Error Handling
* Errors during context querying, reasoning dispatch, policy authorization, module execution, or memory persistence MUST NOT be swallowed.
* Any unhandled error during an active agency loop MUST transition the current action to failed, log a `.commandRejected` or failure event, and leave `AgentRuntime` in a consistent state holding invariants.

## 6. Test & Verification Requirements for M6

When M6 implementation begins (M6.1+), the test suite MUST verify:

1. **Pipeline Determinism**: End-to-end execution of Cognition Pipeline with fake providers yields deterministic `Plan` and `Reflection`.
2. **Policy Interception**: Actions requiring unauthorized capabilities are blocked by `PolicyEvaluating`.
3. **Approval Interception**: Actions requiring approval trigger `ApprovalGate` and halt if approval is false.
4. **Actor Concurrency**: Concurrent pipeline invocations maintain actor isolation without data races.
5. **Invariant Preservation**: `AgentRuntime.invariantsHold()` returns `true` after every pipeline execution step.
6. **Import Boundaries**: Architecture integrity tests confirm zero forbidden imports across targets.

---

## 7. M7+ Boundary Isolation

* M6 MUST NOT implement iOS UI screens, SwiftUI view models, or live LLM network adapters.
* M6 MUST NOT introduce external cloud dependencies outside the abstract boundaries defined in M5.
* Real-time audio streaming, background task scheduling, and multi-agent network protocols are deferred to M7+.

## 8. Summary of Normative Invariants

1. **Strict Downward Dependencies**: `PAKernel` -> `PACognition` / `PAAgency` / `PAPolicy` -> `PAModules` / `PAProviders` / `PAMemory`.
2. **Policy Primacy**: No tool, skill, or module execution SHALL bypass `PAPolicy`.
3. **Fail-Closed Execution**: Pipeline errors MUST be propagated and handled explicitly; `try?` IS FORBIDDEN.
4. **Local-First & Auditability**: Memory and events MUST track all cognitive operations locally with trace IDs.
5. **Actor Isolation**: All runtime components MUST be Swift actors or thread-safe sendables.
6. **No Production Mutation in M6.0**: M6.0 is an architectural gate ONLY; zero production runtime code SHALL be introduced in M6.0.
